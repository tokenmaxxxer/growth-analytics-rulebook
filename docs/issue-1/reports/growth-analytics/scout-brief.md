# Scout brief (issue-1)

Mode: 3 concurrent search-angle agents in one turn (funnel/growth
frameworks; experiment-trust standards; deliverable/report write-up
norms). 1 sweep stage, no deepening round needed — the three angles
converged strongly (Kohavi's trustworthy-experiments lineage and
metric-tree/hypothesis-first structure recur across all three), so
judge point 1 found no mismatch to swap and judge point 2 (saturation)
said stop after sweep. Total: 1 stage.

## Must-bes (Kano) the field converges on

- A funnel/growth deliverable must: define stages/events explicitly,
  quantify stage-to-stage drop-off, segment-cut to localize the
  bottleneck, state a bottleneck hypothesis, give one prioritized
  recommendation (not a multi-stage list).
- An experiment-trust deliverable must: check SRM (chi-square, hard
  stop on failure), confirm platform A/A validity, report effect size +
  CI (not bare p-value) against a pre-registered practical-significance
  bar, check guardrail metrics, apply Twyman's-law skepticism to
  surprising wins.
- A proposal (pre-analysis) must pre-register: primary metric,
  hypothesis/expected effect, sample size + duration, guardrails,
  decision rule — all written before data collection/interpretation.
- A rigorous write-up must separate: data source/instrumentation
  caveats, method, results (with CIs), and an explicit limitations
  section — not folded into a footnote.

## Performance axes chosen

1. Rigor of pre-registration (metric/threshold fixed before data) vs.
   post-hoc narrative.
2. Trustworthiness gating (SRM/A-A/guardrails) vs. bare significance
   reporting.
3. Actionability (single prioritized bottleneck + hypothesis) vs.
   descriptive-only reporting.

## Adopt / skip

- Adopt: pre-registration discipline + SRM/A-A/guardrail gate + CI-based
  effect reporting + explicit limitations section — these are the
  convergent must-bes across all three angles and map directly onto
  this role's stated decision boundary (퍼널 병목과 실험 결과가 실제
  개선인지).
- Skip: prescribing a single named framework (AARRR vs. HEART vs. North
  Star) as mandatory — the field treats these as interchangeable lenses
  for stage/metric selection, not a required methodology; mandating one
  would over-constrain a role whose actual mandate is diagnosis +
  trust-verdict, not framework adherence.

## Segment fit

This is an internal analytics/oversight role (verdict-issuing, reads-
only per `write_scope: ""`), closer to Kohavi's experimentation-platform
trust-gate lineage than to a growth-team OKR-setting role — so the
experiment-trust axis (SRM/A-A/guardrails/CI) is weighted as the primary
adopted methodology; the funnel-framework literature (AARRR/HEART/North
Star/cohort) is adopted only as the required-components checklist for
the "funnel diagnosis" deliverable, not as a full second methodology.

## Gap line

Current state (see current-state-survey.md) has zero methodology or
required-component norms for either artifact — `--produces` names the
outputs but a gate never checks their shape. Every must-be above is
therefore new, not already met.
